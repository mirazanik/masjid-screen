1. App Overview & Purpose

MasjidScreen is a fullscreen, landscape-mode Android application designed to run permanently on a TV or large monitor mounted inside a mosque. It serves as a real-time information hub for congregants, showing all prayer-related information without any user interaction needed on the display device.

🕌 Display Device (TV / Monitor)

  • Runs fullscreen, landscape, screen-always-on
  • Shows live prayer times, clock, Hijri date
  • Auto-updates from Firebase in real time
  • Works offline (cached data + local prayer calc)
  • Hidden admin trigger via header swipe/tap

🔐 Admin Panel (Password Protected)

  • Firebase Auth — email/password login
  • Set/edit jamaat (congregation) times
  • Manage hadiths and notices
  • Configure mosque info and location
  • Push OTA app updates

🌐 Cloud Sync

  • Firebase Firestore as backend database
  • Real-time listeners — changes reflect instantly
  • Multiple mosques supported via document IDs
  • Admin writes → Firestore → Room → Display

📡 Local-First Architecture

  • Room SQLite caches all cloud data locally
  • Prayer times calculated on-device (no API)
  • Clock synced via NTP (accurate time)
  • Offline badge shown when disconnected

How to Access Admin Panel

  1. On the display screen, swipe or long-tap the header area (mosque name / date row)
  2. App switches to portrait orientation and shows the Login screen
  3. Enter admin email and password (Firebase Auth credentials)
  4. On successful login, the Admin Dashboard opens with 4 tabs
  5. Tap the back/exit button to return to display screen (orientation switches back to landscape)

Security

  • Firebase Authentication — email/password
  • Firestore rules require request.auth != null for all writes
  • Display screen only reads data — no write access without auth
  • Admin session persists until explicitly signed out
Note: The admin trigger on the display is intentionally subtle — a deliberate swipe gesture on the header. This prevents accidental admin mode entry while the display is in public view.

Jamaat Time Management

Set the congregation (Jamaat) time for each of the 5 daily prayers. Changes are saved to Firebase Firestore and appear on the display screen within seconds.

Fields per Prayer

  • Jamaat Time: Enter in HH:MM (24-hour) format. Validated against waqt boundaries — cannot be set before waqt start or after waqt end.
  • Note (optional): Free text, e.g., seasonal variation times or special event info. Shown in the Notes column on display.

Special: Maghrib "auto" Mode

Setting Maghrib jamaat to auto makes the display show the calculated sunset time as the jamaat time. This updates daily automatically — no admin action needed.

Validation Rules

  • Jamaat time must be after waqt start
  • Jamaat time must be before next waqt starts
  • Times stored in HH:MM string format
  • Validation error shown inline if time is outside valid range

Friday (Jumu'ah)

On Fridays, Dhuhr's label automatically changes to "Jumu'ah" on the display. No admin action needed — this is automatic based on day-of-week detection.

OTA Update (Over-the-Air)

OTA Update: Admin enters an APK download URL and version code. The display app checks its current version — if lower than configured version code, it auto-downloads and installs the new APK silently.
  • APK URL: direct link to the updated APK file
  • Version Code: integer (must be higher than installed version to trigger update)
  • Download happens in background using WorkManager
  • Install prompt shown automatically when download completes

Calculated Data

  • Fajr, Sunrise, Dhuhr, Asr, Maghrib (Sunset), Isha times
  • Waqt end times (= next prayer's start)
  • Makrooh windows (Ishraq, Zawal, Sunset)
  • Hijri (Islamic) date from Android ICU IslamicCalendar
  • Next prayer name and minutes until
  • Current prayer identification

Time Synchronization

  • Clock synced via NTP (Network Time Protocol) at app start
  • Uses Bangladesh Standard Time (UTC+6)
  • Falls back to device clock if NTP unavailable
  • Clock updates every second (1s coroutine ticker)

Hijri Date

  • Calculated from Android ICU IslamicCalendar
  • Admin can set ± day offset for moon-sighting adjustment
  • Displayed in Arabic script and Bengali if language = Bengali

13. Over-the-Air (OTA) Updates

Admin can push app updates to display devices without physical access — useful for TV-mounted displays that are hard to reach.

Update Flow

1. Upload new APK
→
to any file host (CDN, GitHub releases, etc.)
2. Admin sets URL + version
→
in Settings tab
3. App detects new version
→
current version code < configured version code
4. WorkManager downloads APK
→
background download
5. Install prompt shown
→
Android PackageInstaller
6. App updated silently

Requirements

  • APK must be signed with the same keystore as the installed version
  • New version code must be higher than the installed version code
  • Device must have "Install from unknown sources" enabled (or system installer permission)
  • Network connectivity required for download

Technical Implementation

  • Check runs in MainActivity on app start and after Firestore config sync
  • Download handled by WorkManager (background, survives app lifecycle)
  • APK saved to app-private storage
  • Install triggered via Android PackageInstaller or ACTION_VIEW intent
  • FileProvider used to share APK URI securely
Caution: Ensure the APK URL is publicly accessible (or uses authentication headers). The download URL is stored in Firestore — only authenticated admins can change it.

15. Architecture & Data Flow

┌─────────────────── CLOUD ───────────────────────┐ │ Firebase Firestore Firebase Auth │ │ mosques/default/data/ Email + Password │ │ ├── config (mosque info) ───────────────── │ │ ├── jamaat_times Admin only writes │ │ ├── hadith │ │ └── notices/ (collection) │ └─────────────┬───────────────────────┬────────────┘ │ snapshot listener │ auth state ▼ ▼ ┌─────────────────────────────────────────────────┐ │ LOCAL LAYER — Room SQLite Database │ │ ┌──────────────┐ ┌────────────┐ ┌──────────┐ │ │ │ MosqueConfig │ │JamaatTimes │ │ Hadiths │ │ │ └──────────────┘ └────────────┘ └──────────┘ │ │ ┌──────────────────────────────────────────┐ │ │ │ Notices (priority-sorted collection) │ │ │ └──────────────────────────────────────────┘ │ └──────────────────┬──────────────────────────────┘ │ Flow (reactive streams) ▼ ┌─────────────────────────────────────────────────┐ │ ViewModels │ │ DisplayViewModel AdminPanelViewModel │ │ + PrayerCalculator + AdminAuthViewModel │ │ + NtpTimeProvider │ │ + ConnectivityManager │ └──────────────────┬──────────────────────────────┘ │ StateFlow (UI state) ▼ ┌─────────────────────────────────────────────────┐ │ Jetpack Compose UI │ │ DisplayScreen ──── Landscape, Fullscreen │ │ AdminPanel ──── Portrait, Auth-gated │ └─────────────────────────────────────────────────┘

Display Data Flow

  1. FirestoreRepository listens to Firestore snapshots
  2. On change: upserts data into Room via DAOs
  3. Room DAOs expose Flow<T> (reactive queries)
  4. DisplayViewModel collects Room flows + 1s clock ticker
  5. PrayerCalculator computes times from config + current time
  6. DisplayViewModel emits DisplayState via StateFlow
  7. DisplayScreen recomposes on each state change

Admin Write Flow

  1. Admin edits field in Admin Panel UI
  2. AdminPanelViewModel calls AdminRepository.saveXxx()
  3. AdminRepository writes to Firestore via .set()
  4. Firestore snapshot listener fires on display device
  5. FirestoreRepository upserts new data into Room
  6. DisplayViewModel picks up Room change via Flow
  7. Display screen updates — within seconds
